Prerrequisitos Universales del Entorno

• Latencia de propagación de CLI: Al crear registros, reintente los comandos ante demoras de replicación.

• Sintaxis de terminal: PowerShell usa acento grave (`) para multilínea; Bash/macOS usa barra invertida (\).

Fundamentos y Anatomía de Azure CLI (Guía para Nuevos Usuarios)

Estructura jerárquica de comandos: Toda instrucción sigue el patrón: az <servicio> <subgrupo> <acción> [--parámetros]. Por ejemplo: az acr repository list interactúa con el servicio ACR, subgrupo repositorio, y la acción listar.

Parámetro / Flag Propósito Técnico Ejemplo de Uso
--resource-group (-g) Define el contenedor lógico de ciclo de vida en Azure. --resource-group rg-lab-eastus
--name (-n) Nombre del recurso que se está creando o consultando. --name acra1b2c3d4
--registry Nombre del Azure Container Registry destino en ACR Tasks. --registry $env:ACR_NAME
--image Repositorio y etiqueta asignada a la imagen compilada. --image inference-api:v1.0.0

--no-wait / --yes Ejecuta la operación de forma asíncrona sin pedir confirmación. az group delete ... --no-wait --yes

1. azdeploy.py (Automatización de Infraestructura) Infraestructura como Código

Script en Python que orquesta el aprovisionamiento de recursos en Azure sin requerir plantillas Bicep ni Terraform:

  • Variables de entrada (L5-6): Define rg (Resource Group) y location (región). Son los únicos parámetros editables.
  • Resolución agnóstica de CLI (L25-35): _resolve_exe("az") ubica el binario az en Linux/macOS o az.cmd en Windows.
  • Identidad y Hashing único (L60-68, L104-106): Ejecuta az ad signed-in-user show --query id -o tsv para obtener el Object ID de Entra ID. Calcula un hash SHA-1 de 8 caracteres (user_hash) y genera el nombre acr{user_hash}. Motivo: Los nombres de ACR son FQDN globales (<name>.azurecr.io) y deben ser únicos en todo el mundo.
  • Idempotencia en Resource Group (L120-137): Consulta az group exists; si no existe, lo crea con az group create.
  • Aprovisionamiento del ACR (L139-154): Ejecuta az acr create --sku Basic para crear el registro de bajo costo.
  • Exportación Multi-Shell (L71-102): Escribe .env (para Bash: export VAR="...") y .env.ps1 (para PowerShell: $env:VAR = "...") con UTF-8 y saltos LF, garantizando compatibilidad entre terminales.
2. api/Dockerfile (Definición de Contenedor OCI) Contenedor OCI

Especificación de capas para empaquetar el microservicio de inferencia de IA en una imagen estándar:

  • FROM python:3.11-slim: Imagen base oficial de Python sobre Debian mínimo (~150 MB). Reduce la superficie de ataque y el tiempo de transferencia en comparación con imágenes completas.
  • WORKDIR /app: Establece el directorio de trabajo aislado dentro del sistema de archivos del contenedor.
  • RUN pip install --no-cache-dir flask: Instala el microframework web. El flag --no-cache-dir evita almacenar archivos temporales de pip, manteniendo la capa liviana.
  • COPY app.py .: Copia el script del microservicio al directorio de trabajo /app.
  • ENV APP_VERSION=1.0.0 y ENV MODEL_VERSION=v1: Inyecta variables de entorno predeterminadas, desacoplando la configuración del código fuente.
  • EXPOSE 5000 y CMD ["python", "app.py"]: Declara el puerto de escucha y el comando de arranque del servidor.
3. api/app.py (Microservicio de Inferencia de IA) Microservicio REST

Servidor HTTP REST implementado con Flask que simula una API de inferencia de Machine Learning:

  • Ruta /health: Health check probe. Retorna {"status": "healthy", "version": ...}. Esencial para que orquestadores (AKS, Azure Container Apps) comprueben la salud (liveness y readiness).
  • Ruta /predict: Simulación de inferencia. Retorna predicción, nivel de confianza (0.95) y la versión del modelo leída dinámicamente de la variable de entorno MODEL_VERSION.
  • Ruta /: Catálogo de endpoints disponibles (/health, /predict) para autodescubrimiento.
  • Arranque (host='0.0.0.0', port=5000): Vincular el servidor a 0.0.0.0 es mandatorio para permitir conexiones provenientes del exterior del contenedor.

Creación de ACR: Azure Portal (GUI) vs. Azure CLI

Análisis técnico de opciones del asistente: Basics, Redes, Cifrado CMK, Permisos ABAC y Comandos CLI

1. Pestaña "Basics": Dimensionamiento, Disponibilidad y Modelo de Permisos
Identidad, DNS y Zonas

• Nombre del Registro: FQDN global <name>.azurecr.io (5-50 caracteres alfanuméricos en minúsculas sin guiones).

• Location (Región): Región de residencia de datos. Debe alinearse con el cómputo (AKS/ACA) para evitar latencia y costo de egreso.

• Domain name label scope: Mitigación de subdomain takeover (dangling DNS) si se elimina el registro. Opciones: SubscriptionReuse, TenantReuse, ResourceGroupReuse, NoReuse o Unsecure.

• Availability Zones: Distribuye el registro en 3 zonas físicas aisladas en la región (SLA 99.99%). Requiere SKU Premium.

Tiers de Servicio (SKU)

• Basic: 10 GB almacenamiento, 2 webhooks. Diseñado para desarrollo, aprendizaje y pruebas de concepto.

• Standard: 100 GB, mayor tasa de operaciones por minuto. Ideal para producción media con pipelines CI/CD.

• Premium: 500 GB, Geo-replicación multi-región, Private Endpoints, Customer-Managed Keys (CMK) y Zonas.

Modo de Permisos (RBAC vs ABAC)

• RBAC Registry Permissions: Alcance global tradicional (roles AcrPush / AcrPull sobre todo el registro).

• RBAC + ABAC Repository Permissions: Control de acceso basado en atributos. Permite limitar permisos por repositorio individual (ej. permitir que un equipo solo publique en models/nlp:* y no en models/vision:*).

2. Pestañas "Networking" y "Encryption": Aislamiento y Seguridad en Reposo
Conectividad de Red y Endpoints

• Public Access vs. Private Access: Acceso público desde internet (restringible por IP) o aislamiento total usando Private Endpoints (Azure Private Link) con IP privada dentro de una Virtual Network (VNet).

• Dedicated Data Endpoint: Separa el tráfico de control (autenticación y catálogo) del tráfico masivo de descarga de capas (blobs), eliminando cuellos de botella y facilitando reglas de firewall perimetral.

• Protocolo de Red: Soporta IPv4 only o Dual Stack (IPv4 y IPv6) para topologías empresariales.

Cifrado de Capas y Gobernanza (CMK / Tags)

• Microsoft-Managed Key (MMK): Cifrado automático transparente en reposo con claves gestionadas por Microsoft (AES-256). Viene habilitado por defecto sin costo adicional.

• Customer-Managed Key (CMK / BYOK): Control total de las claves criptográficas almacenadas en Azure Key Vault. Permite rotación y revocación instantánea (mandatorio en banca y salud: HIPAA/PCI-DSS; requiere SKU Premium).

• Tags (Etiquetas): Pares Clave: Valor (ej. Project: AI-200) para auditoría y asignación de costos.

3. Equivalencia en Azure CLI: Modos de Aprovisionamiento (az acr create)
az acr create (Comandos de Implementación) CLI vs Portal
Comandos oficiales para aprovisionar el registro reflejando las opciones configuradas en el asistente gráfico:
# Opción A: Modo Laboratorio / Desarrollo (SKU Basic, acceso público, mínimo costo) az acr create ` --resource-group rg-ia-test ` --name acrlabtest2026 ` --sku Basic ` --location eastus ` --admin-enabled false # Opción B: Modo Enterprise / Producción (SKU Premium, Zonas de Disponibilidad, Data Endpoint y Red Privada) az acr create ` --resource-group rg-ia-test ` --name acrprodenterprise2026 ` --sku Premium ` --location eastus ` --zone-redundancy Enabled ` --enable-data-endpoint true ` --public-network-enabled false ` --tags Environment=Production Project=AI-200
Regla de Gobernanza Enterprise: En entornos productivos mantenga --admin-enabled false. La autenticación debe orquestarse exclusivamente mediante Managed Identities o Entra ID con roles RBAC granulares (AcrPush para pipelines CI/CD y AcrPull para clusters de inferencia).

Estructura de ACR, Niveles de Servicio y Desduplicación

Jerarquía OCI, espacios de nombres, artefactos Helm y tiers de escalabilidad (Contenido Oficial PPT)

Organización y Almacenamiento en Azure Container Registry
1. Jerarquía del Registro

• Registro: Servicio privado administrado en Azure (<acr>.azurecr.io).

• Repositorio: Agrupación lógica de imágenes con el mismo nombre (ej. inference-api).

• Artefactos: Imágenes Docker, gráficos de Helm y contenido compatible con OCI.

2. Espacios de Nombres

• Organización Multinivel: ACR permite estructurar repositorios con barras diagonales (/).

• Ejemplo corporativo: myacr.azurecr.io/marketing/campaign:v1.

• Gobierno RBAC: Facilita asignar permisos basados en prefijos de repositorios.

3. Desduplicación de Capas

• Direccionable por contenido: Las capas OCI se indexan por su hash SHA-256 interno.

• Almacenamiento único: Si 50 imágenes usan python:3.11-slim, la capa se almacena una sola vez.

• Ahorro masivo: Minimiza costos de almacenamiento y tiempo de push/pull.

Ciclo de Vida de ACR Tasks y Validación On-Demand

Las 5 fases de build en Azure, inspección OCI, direccionamiento y testing serverless con az acr run

Ciclo de Vida Interno de ACR Tasks (5 Fases en la Nube de Azure):
1. Empaquetado y Carga: Comprime el contexto de ./api en un tarball y lo sube por HTTPS seguro al storage de ACR.
2. Encolado de Tarea: Encola la solicitud y aprovisiona un agente de cómputo efímero y aislado administrado por Azure.
3. Streaming de Capas: Ejecuta las instrucciones del Dockerfile transmitiendo los logs en vivo a su terminal.
4. Inserción en Registro: Publica la imagen terminada directamente en su Azure Container Registry privado.
5. Reporte de Digest y Estado: Genera el hash inmutable SHA-256 y confirma el resultado exitoso (Task Succeeded).

Método de Referencia Sintaxis Técnica Oficial Comportamiento en Producción
Por Etiqueta (Tag) registry.azurecr.io/api:v1.2.0 Puntero legible pero mutable. Un push posterior puede reasignar el tag y provocar discrepancias entre nodos.

# Crear tarea automatizada con disparador por Git commit y token de acceso personal (PAT) az acr task create ` --registry $env:ACR_NAME ` --name build-inference-api ` --image inference-api:{{.Run.ID}} ` --context https://github.com/myorg/inference-api.git#main ` --file Dockerfile ` --git-access-token $PAT

Arquitectura de Solución Enterprise y Caso de Uso Real

Diagrama lógico de referencia, problemáticas de producción en IA y flujo serverless seguro con ACR Tasks

1. Problemáticas Críticas del Mundo Real en Despliegues de Inferencia (Pain Points)
1. Deriva y Sin Docker Local

• Restricción: Estaciones corporativas bloqueadas sin permisos de root ni licencias de Docker Desktop.

• Impacto: Compilaciones heterogéneas ("en mi máquina anda") y fallos de librerías al pasar a la nube.

• Mitigación: ACR Quick Tasks (az acr build) compila en agentes serverless efímeros de Azure.

2. Vulnerabilidades Upstream

• Restricción: Microservicios sobre imágenes públicas (python:3.11-slim) con constantes CVEs de seguridad.

• Impacto: Parcheo manual reactivo y lento que deja los clústeres productivos vulnerables durante semanas.

• Mitigación: Base Image Update Triggers recompila automáticamente la imagen ante parches de la distro.

3. Mutabilidad y Tráfico Público

• Restricción: Clústeres multirregión consumiendo tags mutables (:latest) expuestos a internet público.

• Impacto: Discrepancia binaria entre nodos de inferencia e incumplimiento de normativas (HIPAA/PCI-DSS).

• Mitigación: Inmutabilidad SHA-256 Digest + Private Endpoints (Azure Private Link) + Cifrado CMK.

3. Matriz de Mitigación: Problemática de Producción vs Componente Azure

1. Principios de Aislamiento Perimetral y Segmentación de Red (Zero-Trust)
Plano de Control vs Dedicated Data Endpoint

• Control Plane (acrlab.azurecr.io:443): Gestiona autenticación OAuth 2.0 con Entra ID, metadatos y manifiestos OCI. Filtrado por IP Whitelisting corporativo estricto.

• Data Plane (acrlab.data.eastus.azurecr.io:443): Dedicado al streaming masivo de blobs de capas Docker. Enrutado de forma privada para evitar saturar el plano de autenticación.

Resolución DNS Privada y Private Link

• Private DNS Zone (privatelink.azurecr.io): Vinculada a vnet-prod. Resuelve el FQDN del registro hacia la IP fija interna 10.0.1.5 de la interfaz de red virtual (NIC).

• Zero Egress: Los clústeres de inferencia no requieren gateway NAT ni salida pública para descargar imágenes del registro institucional.

Pregunta 2: Consistencia Estricta en Producción (Oficial PPT Slide 10) Digest SHA-256
Debes implementar una imagen de contenedor en producción y asegurarte de que cada nodo ejecute exactamente la misma versión, incluso si alguien inserta una nueva imagen con la misma etiqueta. ¿Cómo debes hacer referencia a la imagen en el manifiesto de despliegue?

Glosario de Términos, Conceptos Clave y Siglas de Azure

Definiciones normativas OCI y diccionario exhaustivo de acrónimos utilizados en el laboratorio

1. Conceptos Arquitectónicos Centrales de Contenedores y Registro
Azure Container Registry (ACR)
Servicio PaaS administrado y privado basado en OCI que almacena, compila y distribuye artefactos e imágenes para orquestadores de Azure (ACA, AKS, ACI).
ACR Tasks & Tarball Context
ACR Tasks: Compilación serverless en la nube. Tarball (.tar.gz): Archivo empaquetado del contexto local (código + Dockerfile) enviado por HTTPS a Azure.
Digest (SHA-256) vs. Tag
El Digest (@sha256:...) es inmutable y direccionable por contenido. El Tag (ej. :latest) es un puntero mutable que puede sobrescribirse.
Replicación Geográfica
Característica del SKU Premium que sincroniza repositorios en múltiples regiones bajo un único FQDN, reduciendo latencias de descarga y costos de egreso.
Private Link & Data Endpoint
Private Endpoint: Conecta el ACR a una VNet privada. Data Endpoint: Aísla el tráfico pesado de descarga de capas del plano de control.
DNS Scope & acr purge
Domain Name Label Scope: Previene ataques de dangling DNS al liberar FQDNs. acr purge: Tarea programada que elimina imágenes sin tag.
2. Diccionario de Siglas y Acrónimos Técnicos del Módulo
Sigla Significado y Rol en Azure
ACA Azure Container Apps: Plataforma serverless basada en Kubernetes para microservicios y APIs sin gestionar clústeres.
AKS Azure Kubernetes Service: Orquestador administrado de clústeres Kubernetes para arquitecturas de alta escala.
ACI Azure Container Instances: Cómputo serverless bajo demanda para contenedores individuales rápidos sin orquestación.
ARM Azure Resource Manager: Plano de control y API declarativa para desplegar, gestionar y auditar recursos de Azure.
FQDN Fully Qualified Domain Name: Nombre de dominio completo globalmente único (ej. <acr>.azurecr.io).
VNet Virtual Network: Red virtual aislada para comunicación privada y segura entre recursos de Azure.
CI/CD Continuous Integration / Continuous Deployment: Automatización de compilación, pruebas y entrega de software.
RBAC Role-Based Access Control: Autorización basada en roles (AcrPush, AcrPull, Contributor).
TAR / TGZ Tape Archive / Tarball (.tar.gz): Archivo empaquetado y comprimido del contexto de compilación local enviado por HTTPS a ACR Tasks.
Sigla Significado y Rol en Azure
ABAC Attribute-Based Access Control: Autorización granular basada en atributos/etiquetas a nivel de repositorio en ACR.
CMK / BYOK Customer-Managed Key / Bring Your Own Key: Cifrado en reposo controlado por el cliente en Azure Key Vault.
MMK Microsoft-Managed Key: Cifrado transparente por defecto gestionado automáticamente por Microsoft (AES-256).
SKU Stock Keeping Unit: Nivel de servicio, capacidad técnica y tarificación de un recurso (Basic, Standard, Premium).
OCI Open Container Initiative: Estándar universal de la industria para formatos de imagen y runtimes de contenedores.
CVE Common Vulnerabilities and Exposures: Identificador estandarizado de fallos de seguridad en software/imágenes.
JMESPath JSON Query Language: Lenguaje declarativo de filtros usado en el flag --query de Azure CLI.
TSV Tab-Separated Values: Formato de texto plano devuelto por --output tsv para parseo limpio en scripts.
TLS Transport Layer Security: Protocolo criptográfico (TLS 1.3) que cifra el canal HTTPS al subir el tarball y descargar capas OCI.
