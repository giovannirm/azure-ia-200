Módulo 03: Deploy a Containerized Backend API to Azure Container Apps

Despliegue Serverless de APIs en Contenedor con Azure Container Apps, Managed Identity y Secretos Runtime

Alineación Curricular Oficial Microsoft Learn (Curso AI-200T00-A • Examen AI-200): Dominio 1: Contenedores (20% – 25%)
Cubre las competencias oficiales del Módulo 3: Implementación y escalado con KEDA en Azure Container Apps (ACA) (5 días / 120 hrs). Objetivos Oficiales: (1) Aprovisionar entorno serverless y microservicios; (2) Configurar ingress HTTPS, balanceador Envoy y terminación TLS; (3) Integrar Azure Container Registry con System-Assigned Managed Identity (rol AcrPull); (4) Enlazar secretos runtime mediante referencias secretref; (5) Inspección de logs, probes HTTP y escalado dinámico con KEDA. Consulte la Guía de Estudio Oficial AI-200 y el Ejercicio Oficial de Container Apps (30 min).
Prerrequisitos Universales del Entorno

• Azure CLI 2.50+ (64-bit): Requiere arquitectura x64 instalada en C:\Program Files\Microsoft SDKs\Azure\CLI2 para evitar desbordamientos de memoria en CLI y garantizar compatibilidad con extensiones.

• Python 3.10+ y Extensiones CLI: Instalación de extensiones oficiales containerapp y log-analytics para habilitar el plano de control serverless.

• Control de Acceso RBAC: Permisos de Contributor o Owner en el Resource Group, con capacidad de asignación de roles (AcrPull) en el registro de destino.

• Universal Execution Context: Desacoplamiento total de credenciales efímeras de VM de laboratorio (Admin / Pa55w.rd) para operar en suscripciones Pay-As-You-Go, Visual Studio o Azure for Students.

Avisos Críticos y Consideraciones de Azure

• Tolerancia a Latencia Transitoria: La creación del Container Apps Environment puede reportar desconexiones transitorias en la terminal mientras el aprovisionamiento continúa en background.

• Validación de Estado Succeeded: Nunca desplegar la Container App hasta comprobar que properties.provisioningState del entorno devuelve Succeeded (evita error ManagedEnvironmentNotProvisioned).

• Sintaxis de Shell: Uso de acento grave (`) para continuación de línea en PowerShell frente a barra invertida (\) en Bash / Zsh.

• Proveedores de Recursos: Registro mandatario de los namespaces Microsoft.App, Microsoft.OperationalInsights y Microsoft.ContainerRegistry.

Diferenciación Arquitectónica: Azure CLI Extension vs. Azure Resource Provider & Gestión en Azure Portal
Cliente Local Azure CLI Extension (az extension)

• Definición y Arquitectura: Módulo de Python empaquetado (wheel) que amplía dinámicamente el árbol de comandos de Azure CLI en tu máquina sin requerir la reinstalación del ejecutable base del SDK.

• Ubicación y Almacenamiento: Reside estrictamente en el disco del cliente local (~/.azure/cliextensions/ en Linux/macOS o %USERPROFILE%\.azure\cliextensions en Windows).

• Comportamiento en Azure Portal:

– No existe en Azure Portal: Al ser una utilidad del lado cliente, no constituye un recurso en la nube ni se proyecta en la consola web de Azure.

– Distinción Crítica: No confundir con las VM Extensions (agentes de cómputo que se instalan dentro de máquinas virtuales y sí se visualizan en el Portal).

• Auditoría en Terminal: Se inspecciona mediante az extension list -o table y se actualiza con az extension update --name containerapp.

Plano de Control ARM Azure Resource Provider (az provider)

• Definición y Arquitectura: Servicio backend de Azure Resource Manager (ARM) que actúa como la API REST y fábrica de recursos para un namespace dado (Microsoft.App, Microsoft.OperationalInsights, Microsoft.ContainerRegistry).

• Ámbito de Suscripción: Opera a nivel de suscripción de Azure. Si el proveedor no se encuentra en estado Registered, ARM bloquea cualquier despliegue con el error MissingSubscriptionRegistration.

• Inspección y Registro en Azure Portal (GUI):

Azure Portal > Subscriptions (Suscripciones) > [Tu Suscripción] > Settings > Resource providers

1. Búsqueda: Filtrar por el namespace (ej. Microsoft.App).

2. Verificación: Auditar la columna Status (Registered vs NotRegistered).

3. Acción GUI: Seleccionar la fila y pulsar Register (o Re-register) en la barra superior. El estado transiciona de Registering a Registered.

Gestión de Secretos, Variables de Entorno y Modelo de Revisiones

Configuración Segura de Claves de API, Desacoplamiento secretref y Ciclo de Vida (Task 2)

1. Configuración de Secretos y Enlace Runtime (Task 2)
Configuración de Secreto e Inyección como Variable de Entorno Secret Reference (secretref)
Almacene la clave de API como secreto seguro en Azure Container Apps y vincúlela a una variable de entorno mediante la sintaxis secretref:. Esta operación reinicia el microservicio creando una nueva revisión inmutable:
# 1. Almacenar el secreto en el almacén seguro de Azure Container Apps az containerapp secret set ` -n $env:CONTAINER_APP_NAME ` -g $env:RESOURCE_GROUP ` --secrets embeddings-api-key=$env:EMBEDDINGS_API_KEY # 2. Vincular el secreto a la variable de entorno EMBEDDINGS_API_KEY (genera una nueva revisión) az containerapp update ` -n $env:CONTAINER_APP_NAME ` -g $env:RESOURCE_GROUP ` --set-env-vars EMBEDDINGS_API_KEY=secretref:embeddings-api-key
Arquitectura de Seguridad Zero-Trust: La directiva secretref: asegura que el valor del secreto nunca quede expuesto en el portal en texto plano, en la plantilla ARM/Bicep ni en el historial de comandos del shell. El runtime de Container Apps inyecta el valor directamente en el espacio de memoria del proceso en tiempo de ejecución.
2. Modelo de Revisiones Inmutables en Azure Container Apps
Auditoría de Revisiones az containerapp revision
Confirme la creación de la nueva revisión tras la inyección del secreto:
az containerapp revision list ` -n $env:CONTAINER_APP_NAME ` -g $env:RESOURCE_GROUP ` -o table
Sufijo de Revisión: El nombre de la revisión termina con un sufijo incremental como --0000002, indicando que es la segunda instantánea inmutable del contenedor.
Modos de Revisión y División de Tráfico

• Single Revision Mode (Por Defecto): Toda actualización redirige el 100% del tráfico a la nueva revisión una vez que los health probes responden exitosamente (Zero-Downtime Deployment).

• Multiple Revision Mode: Permite tener múltiples revisiones activas concurrentemente para estrategias avanzadas de despliegue:

- Blue/Green: Despliegue de versión sin tráfico, validación de endpoints y cambio instantáneo al 100%.

- Canary Splitting: División porcentual de tráfico (ej. 80% a v1, 20% a v2) con az containerapp ingress traffic set.

AZURE AI-200 • INFRAESTRUCTURA Y TOPOLOGÍA DE RED

Diagrama de Arquitectura Física y Red de Azure Container Apps

Aislamiento de Red, Terminación TLS, Tráfico Norte-Sur / Este-Oeste y Topología VNet

Topología de Red y Fronteras de Aislamiento Físico

Aislamiento de Red y Subred Delegada: Azure Container Apps opera dentro de un entorno Kubernetes serverless completamente administrado por Microsoft. El Container Apps Environment puede inyectarse en una subred dedicada de una VNet del cliente (/23 para perfiles Consumption o /27 para Workload Profiles dedicados) para aislar completamente las comunicaciones privadas.

Tráfico Norte-Sur vs Este-Oeste: El tráfico entrante de Internet (Norte-Sur) termina en el controlador de entrada Envoy con TLS 1.3 gestionado y certificados automáticos. La comunicación entre microservicios dentro del mismo entorno (Este-Oeste) se realiza a través de DNS privado interno y túneles mTLS automáticos, impidiendo la interceptación de paquetes entre réplicas.

Guía Oficial de Resolución de Problemas (Troubleshooting de Microsoft Learn)
Síntoma / Error Observado Causa Raíz Arquitectónica Procedimiento de Diagnóstico y Mitigación
Fallo o Tarea Encolada en ACR Build
(Estado Queued prolongado)		 Agentes de compilación de ACR Tasks saturados o contexto de directorio incorrecto. Liste ejecuciones con az acr task list-runs --registry $ACR_NAME -o table. Cancele la tarea colgada con az acr task cancel-run y reintente el build directamente.
ManagedEnvironmentNotProvisioned
(Al crear la Container App)		 El Container Apps Environment aún no ha alcanzado el estado de aprovisionamiento Succeeded. Ejecute az containerapp env show -n $ACA_ENV -g $RG --query properties.provisioningState -o tsv y espere a que retorne Succeeded antes de crear la app.
ImagePullBackOff / 403 Forbidden
(Error al extraer imagen desde ACR)		 Falta el rol RBAC AcrPull o la identidad administrada no se ha propagado en Entra ID. Compruebe la identidad con az containerapp identity show. Valide que la asignación de rol en el ACR tenga el scope adecuado y permita 1-2 minutos de propagación.
HTTP 502 / 503 Bad Gateway
(Tras el despliegue inicial)		 El contenedor está realizando un arranque en frío (cold start) o el puerto de Gunicorn no coincide con --target-port. Inspeccione los logs en tiempo real con az containerapp logs show --follow. Confirme que Gunicorn está escuchando en 0.0.0.0:8000 y verifique revisiones activas.
Creación Incompleta de App
(NameResolutionError / Max retries)		 Latencia de Azure que provocó una creación parcial sin credenciales de registro asociadas. Consulte az containerapp show --query properties.configuration.registries. Si devuelve null, configure el registro con az containerapp registry set.
Secreto No Detectado en /
(embeddings_api_key_configured: false)		 El secreto fue creado en ACA pero no se vinculó a la variable mediante la sintaxis secretref:. Verifique con az containerapp secret list -o table y reejecute az containerapp update --set-env-vars EMBEDDINGS_API_KEY=secretref:embeddings-api-key.
Reglas de Oro de Arquitectura para el Examen AI-200 (PPT y Microsoft Learn)

• 1. Identidad Administrada en ACR: Para servicios de IA de producción que extraen múltiples imágenes, utilice siempre System-Assigned Managed Identity con AcrPull en lugar de credenciales maestras de administrador.

• 2. Inmutabilidad de Revisiones: Cada modificación de imagen, secreto o variable de entorno crea una nueva revisión inmutable en Container Apps. Esto permite auditoría de versiones y reversión segura (rollback).

• 3. Desacoplamiento de Secretos: Nunca inserte API keys en la imagen de contenedor ni en el archivo YAML en texto plano. Utilice el almacén de secretos de Container Apps y haga referencia a ellos con secretref:.

• 4. Delimitación de Entorno: Agrupe aplicaciones que comparten ciclo de vida, dominio de red o destino de observabilidad en el mismo Container Apps Environment para habilitar comunicación Este-Oeste por DNS interno.

AZURE AI-200 • GLOSARIO TÉCNICO Y DICCIONARIO DE SIGLAS

Glosario de Términos, Conceptos Clave y Siglas de Azure

Definiciones Normativas de Azure Container Apps, Diccionario de Siglas y Mapa Curricular Oficial

1. Conceptos Arquitectónicos Centrales de Azure Container Apps
Container Apps Environment
Límite lógico de red y aislamiento que agrupa aplicaciones de contenedor, proporcionando dominio DNS interno compartido, VNet y destino unificado de Log Analytics.
Revision (Revisión Inmutable)
Instantánea inmutable con versiones de una Container App generada automáticamente ante cambios de imagen o configuración, con soporte de división de tráfico.
Managed Ingress (Envoy)
Controlador de entrada serverless que proporciona terminación TLS 1.3 automática, certificados SSL gratuitos, balanceo de carga HTTP/2 y enrutamiento externo o interno.
KEDA (Escalado por Eventos)
Motor de autoescalado basado en eventos integrado en ACA que ajusta las réplicas dinámicamente de 0 a N según peticiones HTTP concurrentes o mensajes en cola.
Secret Reference (secretref)
Directiva declarativa que inyecta valores confidenciales en variables de entorno en memoria sin exponerlos en el portal, plantillas ARM ni historial del shell.
System-Assigned Identity
Identidad de Microsoft Entra ID ligada al ciclo de vida del contenedor que permite autenticarse sin contraseñas contra Azure Container Registry con el rol AcrPull.
Scale-to-Zero (Escalado a 0)
Capacidad serverless de apagar todas las réplicas en ausencia de tráfico entrante, suspendiendo totalmente los costes de procesamiento hasta la siguiente solicitud.
Log Analytics Workspace
Repositorio analítico centralizado donde persisten los registros de consola (stdout/stderr) y del sistema de ACA, consultables mediante lenguaje KQL.
Workload Profiles
Modelo de dimensionamiento de cómputo que permite seleccionar entre perfiles Serverless Consumption o perfiles dedicados con hardware optimizado para memoria o GPU.

Sigla Significado y Rol en Azure

TLS Transport Layer Security: Cifrado criptográfico TLS 1.3 para canales HTTPS de entrada.

SKU Stock Keeping Unit: Nivel de tarificación y capacidades del servicio (Basic, Premium, Consumption).
TSV Tab-Separated Values: Formato de salida tabular para extracción de valores en Azure CLI.
