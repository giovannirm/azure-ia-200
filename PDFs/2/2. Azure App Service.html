Prerrequisitos Universales del Entorno

• Suscripción de Azure: Requiere plan con soporte de App Service Linux dedicado (ej. P0v3 o B1).

• Azure CLI: Versión 2.50+ instalada localmente o en Azure Cloud Shell (az --version).

• Python 3.10+: Para ejecutar scripts de despliegue automatizado de infraestructura (azdeploy.py).

• Permisos RBAC: Roles Contributor y User Access Administrator u Owner para asignación de roles.

• Sin Docker local: No se requiere Docker Desktop; la imagen se compila en ACR Tasks y se corre en PaaS.

Consideraciones y Avisos Críticos de Azure

• Sistema Operativo Linux: Los contenedores personalizados requieren un App Service Plan con el flag --is-linux.

• Unicidad global de DNS: El nombre de la Web App debe ser único mundialmente (<app>.azurewebsites.net).

• Mapeo de puertos en contenedor: Por defecto App Service asume el puerto 80; si difiere, requiere WEBSITES_PORT.

• Almacenamiento en contenedor: El sistema es efímero salvo que se active WEBSITES_ENABLE_APP_SERVICE_STORAGE=true.

Estructura del Proyecto Fuente: Paquete oficial descargado en CODE/2. app-svc-container-python/ que contiene la API Flask de procesamiento documental (api/main.py), el archivo de construcción OCI (api/Dockerfile), requisitos (api/requirements.txt), el script de despliegue (azdeploy.py) y el archivo de prueba (document.txt).
Fundamentos y Jerarquía de Azure CLI para Azure App Service

Estructura jerárquica de comandos: El ciclo de vida de Web App for Containers se administra mediante dos grupos: az appservice plan (asigna cómputo físico, CPU y memoria) y az webapp (gestiona la configuración lógica, identidades, contenedores y variables).

Mapeo de Puertos y Enrutamiento Interno

• Detección automática: App Service analiza el manifiesto de la imagen y detecta la cláusula EXPOSE 80 del Dockerfile.

• Proxy inverso frontal: El balanceador PaaS recibe solicitudes públicas en los puertos 80/443 (HTTPS) y las redirige internamente al puerto en el que escucha Gunicorn (puerto 80).

• Variable WEBSITES_PORT: Si la aplicación escucha en un puerto personalizado (ej. 5000 o 8080), es obligatorio definir WEBSITES_PORT=5000 en Application Settings.

• Enlace a 0.0.0.0: En contenedores Docker, la aplicación debe enlazar a 0.0.0.0 (no a 127.0.0.1), de lo contrario el proxy de App Service no podrá alcanzar el servicio.

Timeout de Inicio del Contenedor

• Límite predeterminado: App Service espera hasta 230 segundos a que el contenedor responda a las sondas HTTP iniciales antes de abortar el arranque.

• Modelos pesados de IA: Si la aplicación descarga embeddings o inicializa pesos en memoria durante el arranque, este tiempo puede ser insuficiente.

• Variable de ampliación: Se debe configurar WEBSITES_CONTAINER_START_TIME_LIMIT=600 (configurable hasta un máximo de 1800 segundos / 30 minutos).

• Diagnóstico de fallos: Si el contenedor se reinicia en bucle (crash loop), revise los logs del motor Docker en Kudu.

AZURE AI-200 / AZ-204 • FASE 4: SEGURIDAD ZERO-TRUST E IDENTIDAD

Seguridad Zero-Trust con Identidad Administrada y Rol AcrPull

Eliminación de contraseñas estáticas mediante System-Assigned Managed Identity y asignación RBAC en Entra ID

Principio de Mínimos Privilegios (Zero-Trust): Nunca habilite la cuenta --admin-enabled true en registros de producción. Utilice identidades administradas asignadas por el sistema (MSI): no requieren almacenar credenciales en App Settings, rotan automáticamente cada 24 horas y restringen el acceso exclusivamente a extracción con el rol AcrPull.
Paso 4.1: Habilitar la Identidad Administrada Asignada por el Sistema en la Web App
az webapp identity assign (--query principalId) Microsoft Entra ID
Active la identidad administrada en la Web App para que Azure registre un Service Principal en Entra ID:
# 1. Habilitar la identidad asignada por el sistema y capturar el principalId PRINCIPAL_ID=$(az webapp identity assign ` --resource-group $RESOURCE_GROUP ` --name $APP_NAME ` --query "principalId" ` -o tsv) # 2. Verificar el Object (Principal) ID asignado en Entra ID echo "Managed Identity Principal ID: $PRINCIPAL_ID"
Ciclo de vida de System-Assigned Identity: La identidad comparte el ciclo de vida del recurso Web App. Si la aplicación se elimina, Azure elimina automáticamente el Service Principal en Entra ID y todas sus asignaciones de roles.
Paso 4.2: Asignar el Rol RBAC AcrPull en el Ámbito del Azure Container Registry
az role assignment create (--role AcrPull --scope $ACR_ID) RBAC Authorization
Obtenga el identificador de recurso de ACR y asigne el rol de extracción mínima a la Web App:
# 1. Obtener el Resource ID completo del registro ACR ACR_ID=$(az acr show ` --resource-group $RESOURCE_GROUP ` --name $ACR_NAME ` --query "id" ` -o tsv) # 2. Otorgar permiso de extracción (AcrPull) a la identidad de la Web App az role assignment create ` --assignee $PRINCIPAL_ID ` --role "AcrPull" ` --scope $ACR_ID # 3. Comprobar la asignación de rol activa az role assignment list --assignee $PRINCIPAL_ID --output table
Definición del rol AcrPull: Autoriza la acción Microsoft.ContainerRegistry/registries/pull/read. Impide que un atacante que comprometa la Web App pueda modificar imágenes o publicar artefactos maliciosos (requeriría AcrPush).

Arquitectura del Volumen /home Persistente

• Comportamiento efímero estándar: En contenedores Linux sin almacenamiento de App Service, los archivos creados en el contenedor se escriben en memoria o disco efímero y se destruyen al reiniciar la app.

• Montaje CIFS/NFS: Al activar WEBSITES_ENABLE_APP_SERVICE_STORAGE=true, la infraestructura de Azure monta un volumen compartido cifrado en /home.

• Resiliencia de documentos: Todos los análisis JSON guardados por la API en /home/processed sobreviven a reinicios, despliegues y conmutaciones por error.

Diagrama de Arquitectura Lógica de la Solución

Caso de uso empresarial de procesamiento inteligente de documentos, desacoplamiento PaaS y autenticación Zero-Trust

Problemática Empresarial: Una entidad corporativa procesa diariamente contratos confidenciales y reportes financieros mediante modelos de IA. Anteriormente utilizaban servidores locales con credenciales maestras compartidas en texto plano, sin persistencia ante fallos y con caídas frecuentes durante picos de carga.

Solución de Arquitectura en Azure: Migración a un microservicio en contenedor alojado en Azure App Service en Linux. BLUEPRINT DE ARQUITECTURA LÓGICA (DRAW.IO CANVAS ESTILO VECTORIAL) Zero-Trust & Persistent PaaS
Secuencia Lógica: (1) Ingesta: Peticiones HTTPS entrantes balanceadas al contenedor Flask en el puerto 80. (2) Autenticación Zero-Trust: App Service presenta el token de Entra ID vía Managed Identity sin credenciales fijas. (3) Descarga OCI: Kudu extrae las capas de docprocessor:v1 desde ACR con permisos AcrPull. (4) Persistencia Segura: Los análisis procesados se escriben en /home/processed respaldado por Azure Storage resiliente.

AZURE AI-200 / AZ-204 • INFRAESTRUCTURA Y TOPOLOGÍA DE RED

Diagrama de Arquitectura Física y Red de App Service

Topología de red perimetral, plano de datos aislado, servicio IMDS y montaje CIFS/SMB cifrado

Topología de Red y Fronteras de Aislamiento Físico

Aislamiento de Cómputo: El App Service Plan Linux aprovisiona instancias de máquinas virtuales dedicadas protegidas por Azure Hyper-V y cgroups. El tráfico de producción ingress en el puerto 443 es terminado en el balanceador frontal PaaS de Azure y reenviado por un canal local al contenedor Docker en 0.0.0.0:80.

Autenticación Criptográfica IMDS: La identidad administrada consulta internamente al Azure Instance Metadata Service (http://169.254.169.254/metadata/identity/oauth2/token), una dirección local no enrutable a Internet. Los tokens obtenidos son enviados por TLS 1.3 hacia el plano de datos de Azure Container Registry.

TOPOLOGÍA DE RED Y PLANO FÍSICO (DRAW.IO CANVAS ESTILO VECTORIAL) TLS 1.3 • IMDS 169.254.169.254 • SMB Port 445
Aspectos Clave de Seguridad de Red: (1) Terminación TLS: El balanceador PaaS frontal de Azure gestiona certificados SSL y mitiga ataques de capa 7 antes de alcanzar el nodo Linux. (2) Cero Tráfico de Credenciales: El daemon IMDS entrega tokens en memoria sin exponer secretos en el canal de red público. (3) Montaje de Red Cifrado: El almacenamiento en /home se comunica por canal CIFS interno cifrado con AES-256 gestionado por Microsoft.

Disección Exhaustiva del Código Fuente y Configuración

Análisis técnico de azdeploy.py, contenedor OCI en Dockerfile y contratos REST en main.py

1. Script de Despliegue de Infraestructura: azdeploy.py

Hash Criptográfico y Unicidad Global: En las líneas 121-127, la función _derived_names(user_object_id) calcula un resumen SHA-1 truncado a 8 caracteres basado en el ID de Entra ID del usuario. Esto garantiza que acr<hash>, plan-docprocessor-<hash> y app-docprocessor-<hash> cumplan con la restricción de FQDNs únicos mundiales en Azure sin colisiones.

Resolución Multiplataforma de Binarios: En _resolve_exe() (líneas 27-37), utiliza shutil.which() para resolver automáticamente az.cmd en Windows o az en entornos Unix/macOS, almacenando el ejecutable en caché para optimizar llamadas repetitivas.

Generación Dual de Entorno: En write_env_files() (líneas 88-119), genera en paralelo .env (usando export KEY="VAL" con escapado Bash) y .env.ps1 (usando $env:KEY = "VAL" con acentos graves de PowerShell) en codificación UTF-8 pura con saltos de línea LF.

2. Especificación del Contenedor OCI: api/Dockerfile

Imagen Base Hardened (Línea 1): FROM python:3.11-slim reduce drásticamente el tamaño del artefacto (de ~1 GB a menos de 150 MB) y elimina librerías de compilación innecesarias, mitigando vectores de vulnerabilidad (CVEs).

Higiene de Capas (Líneas 6-7): Instala dependencias copiando únicamente requirements.txt con pip install --no-cache-dir. Esto previene que los archivos temporales de pip se incorporen en las capas inmutables de la imagen Docker.

Directorio de Persistencia (Línea 13): RUN mkdir -p /home/processed asegura que el punto de montaje exista antes de que App Service enlace el volumen compartido CIFS.

Servidor WSGI de Producción (Líneas 16-19): Expone EXPOSE 80 y define CMD ["gunicorn", "--bind", "0.0.0.0:80", "--workers", "2", "--access-logfile", "-", "main:app"]. Ejecuta 2 workers concurrentes enlazados a todas las interfaces para atender peticiones enrutadas por el proxy de App Service.

3. Microservicio Flask de Procesamiento: api/main.py

Desacoplamiento de Configuración (Líneas 14-20): Extrae variables operativas mediante os.getenv() con valores de contingencia (STORAGE_PATH="/home/processed", MAX_DOCUMENT_SIZE_MB=50, PROCESSING_TIMEOUT_SECONDS=30), permitiendo modificar el comportamiento desde Application Settings sin recompilar la imagen.

Resiliencia de Almacenamiento (Líneas 30-37): La función ensure_storage_directory() valida y recrea la ruta persistente STORAGE_PATH ante caídas o reinicios del nodo host.

Contratos de Endpoints REST:

• GET /health: Endpoint ligero que retorna {"status": "healthy"} para los sondeos de disponibilidad (Liveness Probe) de App Service.

• POST /process: Genera un uuid4(), evalúa el límite de tamaño, calcula métricas de caracteres/palabras, extrae entidades mock con índices de confianza, genera análisis de sentimiento y escribe el resultado en STORAGE_PATH/<doc_id>.json.

• GET /documents & GET /documents/<id>: Inspecciona el volumen montado y expone el catálogo histórico de documentos analizados.

A) Habilitar la cuenta de administrador en ACR y configurar DOCKER_REGISTRY_SERVER_PASSWORD en la Web App.
B) Habilitar System-Assigned Managed Identity en la Web App, asignar el rol AcrPull en el ACR y configurar acrUseManagedIdentityCreds=true.

B) Escalar el App Service Plan a un nivel P3v3 con más memoria RAM.

✓ Respuesta Correcta: A) Configurar WEBSITES_ENABLE_APP_SERVICE_STORAGE=true en la Web App

Glosario de Términos, Conceptos Clave y Siglas de Azure

Definiciones normativas de Azure App Service, diccionario de siglas y mapa curricular oficial

1. Conceptos Arquitectónicos Centrales de Azure App Service
App Service Plan (ASP)
Unidad de cómputo físico/virtual que determina la región, el número de instancias, el SO (Linux/Windows), vCPUs y memoria RAM asignados a una o varias Web Apps.
Web App for Containers
Servicio PaaS administrado que ejecuta contenedores Docker/OCI en Linux con balanceo de carga integrado, certificados SSL gratuitos y escalado automático.
System-Assigned Identity
Identidad administrada ligada al ciclo de vida del recurso en Microsoft Entra ID. Proporciona autenticación sin contraseñas para interactuar con ACR y Key Vault.
Almacenamiento Persistente /home
Volumen de red compartido (SMB/CIFS) respaldado por Azure Storage montado en /home cuando WEBSITES_ENABLE_APP_SERVICE_STORAGE=true.
Kudu / SCM Engine
Plano de control y motor de gestión de App Service accesible en <app>.scm.azurewebsites.net, encargado de pulls de imagen, WebSSH y telemetría de log.
Container Logging Stream
Mecanismo de captura y retransmisión en tiempo real de los flujos stdout y stderr del contenedor Docker hacia Azure CLI y Azure Monitor.
2. Diccionario de Siglas y Acrónimos Técnicos del Módulo
Sigla Significado y Rol en Azure
AAS Azure App Service: Plataforma PaaS administrada para hospedar aplicaciones web y contenedores.
ASP App Service Plan: Asignación de recursos de proceso (CPU, memoria, SKU y escala) para Web Apps.

SCM Site Control Manager: Endpoint administrativo aislado en <app>.scm.azurewebsites.net.
FQDN Fully Qualified Domain Name: Nombre de dominio completo (ej. <app>.azurewebsites.net).
Sigla Significado y Rol en Azure
TLS Transport Layer Security: Protocolo criptográfico (TLS 1.3) que cifra el canal HTTPS de la Web App.
CIFS / SMB Common Internet File System: Protocolo de red usado para montar /home desde Azure Storage.
IMDS Instance Metadata Service: Endpoint local 169.254.169.254 para emisión de tokens Entra ID.
SKU Stock Keeping Unit: Nivel de tarificación y capacidad de cómputo (Basic B1, Premium P0v3).
WSGI Web Server Gateway Interface: Interfaz estándar entre servidores web (Gunicorn) y Python Flask.
REST Representational State Transfer: Arquitectura de servicios web sin estado sobre protocolo HTTP.
CORS Cross-Origin Resource Sharing: Mecanismo de seguridad para autorizar peticiones entre dominios.
ARM Azure Resource Manager: Plano de control declarativo para gestionar infraestructura en Azure.
CVE Common Vulnerabilities and Exposures: Identificador público estandarizado de fallos de seguridad.
